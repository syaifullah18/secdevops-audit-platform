# @sdap/api / db

PostgreSQL persistence layer with Drizzle ORM for the SecDevOps Audit Platform.

Owner: workstream **WS3** (see `docs/workstreams/WS3.md`).

## Architecture

This module implements the unified `Store` interface specified in `@sdap/core` (`packages/core/src/store.ts`).

### Tables & Schema (`schema.ts`)

- `projects`: Tenant/project configurations. Enforces multi-tenant isolation via `client_id`.
- `policies`: Gate evaluation rules, enforce vs report-only mode, and SLA timetables.
- `runs`: Audit runs, trigger metadata, commit hashes, scope boundaries, token usage, and lifecycle status.
- `run_phases`: Composite primary key `(run_id, name)` tracking per-phase status and token usage.
- `slices`: Fine-grained work units inside phases with attempt histories stored as `jsonb`.
- `findings`: Canonical findings table with unique constraint on `(project_id, fingerprint)` and index on `secondary_fingerprint`.
- `triage_events`: Append-only audit log of manual status transitions and ownership changes.
- `exceptions`: Accepted risks (with expiry) and false positives keyed by `project_id` and `fingerprint`.
- `events`: Append-only platform event log with unique constraint on `(run_id, seq)` for monotonic replay.
- `decisions`: System 1 (Jev) calibrated decisions and learning loop outcomes.

### Multi-Tenant Isolation

Every read returning projects, runs, or findings enforces caller `AccessScope`:

- `scope.clientIds === "*"`: platform administrator access across all tenants.
- `scope.clientIds: string[]`: strictly joins `projects` on `project_id` and filters by `projects.client_id IN (...)`. Unmatched or empty scopes return zero records.

### Deduplication & Upsert Semantics

`findings.upsert` implements the `mergeFindings` semantics from `@sdap/normalizer`:

1. Queries for existing records matching primary `(project_id, fingerprint)`.
2. If not matched, queries by `secondary_fingerprint` to detect relocated code or renamed functions.
3. Carries forward initial identity (`id`), origin timestamps (`firstSeen`, `firstRun`), and triage state (`status`, `owner`).
4. Updates `lastSeen`, `sourceRun`, `location`, `trace`, and `evidence`.
5. Recomputes SLA due date on verified severity changes or regression (`fixed` re-confirmed).

### Migrations (`apps/api/drizzle/`)

SQL migrations are generated by `drizzle-kit`:

```bash
pnpm --filter @sdap/api exec drizzle-kit generate --dialect=postgresql --schema=src/db/schema.ts --out=drizzle
```

### Testing

Database integration tests live in `apps/api/test/store.test.ts`. When `DATABASE_URL` is unset, the tests skip cleanly with a notice.
To run integration tests against a real PostgreSQL instance:

```bash
DATABASE_URL=postgres://user:pass@localhost:5432/sdap pnpm --filter @sdap/api test
```
